## 建置假設（可改，改了只動 P01 的 Task 1）

| 項目 | 值 |

## 模組

| 模組 | 內容 | 依賴 |
| --- | --- | --- |
| `gigaxfer-core` | 無 Spring、無 DB。FileIdentity、PathLayout、Manifest 編解碼、SHA-256、NFS 有界執行器、Finalize 協議、rediscovery、Policy / config 資料模型與驗證 | Jackson |
| `gigaxfer-library` | Spring Boot starter。`/policy` client + fallback 檔、statfs WriteGate、`/locate` 的 exists / read、Local Transaction 指標 | core |
| `gigaxfer-sync-service` | Spring Boot app。schema、掃描 ingest、Node 間端點、Target puller、對帳、自查、rebuild、清道夫、ops API、config 啟用 | core |
| `gigaxfer-cli` | 包 ops API、依 Policy 扇出 `/status` | core（Policy 模型） |
| `gigaxfer-nfs-acceptance` | SR-03 六項、D12 修 failover、D3b 隔離的驗收腳本；在真實 NAS 上跑 | core, library |

## 每份計畫的固定規則

- 一個 git worktree、一個 agent、一個 OpenSpec change（`/opsx:propose` 從該 plan 產 proposal / specs / tasks）。
- 每個 task 以測試先行，`mvn -q -pl <module> test` 綠燈才 commit。
- 對外契約（HTTP 欄位、DB 欄位、manifest 欄位）一律以 system-design.md 為準；計畫與設計衝突時改計畫，並在 design-decisions.md 記一列。
- 「禁止整檔進記憶體」與「每個 NFS 操作經有界執行器」是 code review 硬規則。
