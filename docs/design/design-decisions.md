# System Design 決策紀錄（grilling 2026-09-21 起）

供撰寫 docs/design/system-design.md 用。詞彙見 CONTEXT.md，需求見 spec v0.3。

| # | 決策 | 封閉的需求 |
| --- | --- | --- |
| D1 | Source Ready 權威紀錄 = NFS 上與檔案同目錄的 `.manifest`（identity、Data class、size、digest、Finalize 時戳）；本地 DB 只是可由 NFS 全掃重建的索引與工作狀態 | FR-02, RR-02, T18, T29 |
| D2 | NFS 路徑由 Framework 從 identity 推導：`<namespace>/<data class>/<yyyy-mm-dd>/<HH>/<logical key>`，日期時間為 Finalize 時 Source 時鐘；Application 不自選路徑 | FR-04, RC-01, §17 inspection |
| D3 | Finalize 協議（v2，修正並發與對稱）：① 內容寫 `<key>.<uuid>.writing` + fsync；② `<key>.manifest` 以 O_EXCL create + write + fsync（EEXIST → 讀既有 manifest 比 digest：同 → 冪等成功、不同 → CONFLICT）；③ `link(<key>.<uuid>.writing, <key>)`——目標已存在則原子失敗，**成功 = commit point = Source Ready**；④ unlink `.writing`。兩端一致：**`<key>` 存在 = Ready**（Target 亦以 link 發布）。Framework 額外 NFS 成本 = 每筆 1 create + 1 fsync + 1 link + 1 unlink。Manifest 單行 JSON 含 schema_version、uuid。Rediscovery：manifest 有 + `<key>` 有 = Ready；manifest 有 + `<key>` 無 + `.writing` 有 → 補 link；manifest 有 + 兩者皆無 → Application 從未拿到 SUCCESS，標 manifest Abandoned；只有 `.writing` = Writing / Abandoned 候選 | FR-02, FR-03, FR-04, SR-03, SR-04, SR-06, T20, T29 |
| D3a | Finalize 冪等重試規則（PENDING_CONFIRMATION 後）：manifest EEXIST 且內容相同 → 續行；不同 → FR-04 conflict；link EEXIST 且 `<key>` digest 等於 manifest → 已完成；manifest 半截（parse 失敗）→ 以 O_EXCL 失敗處理，改走 unlink + 重建。NFS 不可靠性被壓縮為「Finalize 可能需呼叫兩次」，不會留下狀態不明 | SR-04, FR-04, T29 |
| D3b | NFS mount 要求：Application 主機與 sync 主機皆用 `hard`（不假失敗，hang 交給 SR-05 隔離）；library 以獨立 thread + timeout 包每個 NFS 操作；sync 主機另加 `lookupcache=positive`、調低 `acdirmax` 以縮短新檔可見延遲。以上列入 SR-03 驗證項 | SR-02, SR-03, SR-05 |
| D4 | digest 由 Application 端 library 於 write 時 streaming 計算，Finalize 直接寫入 manifest；不重讀、不重算 | IR-01, DG-02 |
| D5 | 每 Node 單一 sync 主機、單一 process，靠監控快速重啟；不做 active-standby；sync service 停機只影響 lag 不影響 Local Transaction | DG-02, DG-05, T06 |
| D5 註 | 應有集合 = NFS manifest × Policy（NFS 為真相）；義務進度 = sync service 本地 DB（可由 manifest 全掃 + 向 Target 查 Completion evidence 重建）；Application 不碰 DB | RR-02, RR-03 |
| D7 | Application 現有 DB 為每 Phase 自有（Node-local）；sync service 共用同一顆 DB、獨立 schema，sync tables 僅由 sync service 寫入；Application 的「檔案已 Ready」記帳不是 Framework 真相 | §1.2, DG-01, RR-02 |
| D8 | Application 整合規則：write → Finalize → 拿到 SUCCESS 才 commit 業務交易並記錄 identity；PENDING_CONFIRMATION 時不 commit，重試 Finalize 至確定；重跑交易前先 exists(identity)。Finalize 後 rollback 產生的孤兒 Ready 檔為可接受浪費。Framework 不參與 Application 的 DB 交易 | SR-01, SR-04, T29 |
| D9 | Node-local DB 為 Oracle；本機開發跑不起 Oracle → SQL 保持可攜（JPA / 標準 SQL、不用 Oracle 專屬語法），本機與單元測試用 H2 Oracle mode，CI 用 Oracle Free container 跑整合測試。單一 sync process 為唯一寫入者，不需要 row-level 搶鎖（SKIP LOCKED） | D5, D7 |
| D10 | 掃描三層共用同一段冪等 ingest：增量掃（當前 + 前一小時，每 N 秒）、全量對帳掃（最近 D 天，預設 7，每 M 小時，附截止點與覆蓋範圍）、重建掃（人工觸發、全部）；超出 D 天的範圍在 metric 揭露為未對帳 | RC-01, RC-02, RC-04, T11 |
| D11 | Writing / Abandoned 由掃描順手判定：`.writing` 或無 manifest 的內容檔 mtime 超過 TTL（預設 24h，operational policy）→ DB 記 Abandoned，檔案留原地不搬，掃描忽略；實際刪除依 RT-01 Framework 清理政策 | FR-02, FR-03, RT-01 |
| D12 | 傳輸 = Target pull over HTTP：Target sync service 週期 `GET /pending?target=<self>&limit=N`（Source 回該 Target 最舊 N 筆「未完成且 next_attempt_at 已到」的義務，附 manifest 欄位；**無 cursor**）→ `GET /file/<identity>` 兩端 streaming（Source 從自身 NAS 讀、Target 寫自身 NAS 同路徑 `.writing` 並以 DigestInputStream 驗 digest；禁止整檔進記憶體）→ size/digest 符合則 rename 發布、DB 寫 received row → `POST /report {kind: DONE}`。Target 唯一狀態 = in-memory in-flight set；重複拿到同一筆先查 received 表，冪等。`/report` 遺失（T19）：下輪 pending 重拿 → Target 見正式路徑已有檔 → 重算該檔 digest 對基準 → 補 row、重送 DONE，不重下載。**不寫 `.evidence` 檔**；Target DB 遺失 → 掃正式檔重算 digest 重建。整檔重傳、size-based timeout；續傳留待 GB 級 | RR-01, RR-03, RR-04, FR-03, IR-02, T08, T19 |
| D12a | 失敗處理：Target 單筆失敗刪 `.writing`、`POST /report {kind: FAILED, reason}`；**退避狀態只在 Source**：收到 FAILED 設該義務 next_attempt_at（指數退避，上限 15 min）、累計次數，`/pending` 自動排除未到期者；反覆 digest 不符 / 4xx → QUARANTINED；Target 回報 CAPACITY → BLOCKED。Target 停機 = 不來拉，Source 以「該 Target 上次 pending 時間」staleness 推導 UNREACHABLE，不需 circuit breaker / 429 / 探測。Catch-up 節奏由 Target 依自身 NAS 負載決定（並發、bytes/s 為 Target 端 operational policy） | RR-04, RR-05, §14, §16, T12, T16, T17 |
| D12 否決 | Source push（需三層流控）、NFS-to-NFS 直搬（遠端 NAS hang 污染本機 NFS client，違反 SR-05）、rsync（仍需 Target 服務做驗證與 evidence）、NAS 原生複寫（volume 級、不可依 Data class 選 Target、發布時機不受控） | SR-05, DG-01 |
| 事實 | 目前實際單一 Phase 最長停機約 6 小時；spec 的 24 小時維持為容量與驗收 envelope（約 4× 餘裕），不下修 | §1.1, §18, RT-02 |
| D6 | 新檔發現 = 純掃描（D10 三層），不做 library → sync service 通知；正常 lag ≈ 掃描間隔 + 目錄 cache（D3b 調參後 ~10–15 s）。若 §18 lag SLO 要求秒級，再加 HTTP fire-and-forget 通知（純加法） | RC-01, DG-02 |
| D13 | `/pending` 排序 = source_ready_at FIFO；不做 Data class 優先級、不分快慢通道（留為純加法） | RR-05, §16 oldest_unfinished_age, §20 |
| D14 | Node 間 HTTP 認證 = Fab 內 shared token（header）+ HTTPS；token 為 operational policy 可輪替；不做 mTLS、不裸跑 | DG-04, §13, §17 |
| D15 | Target 端索引：已發布檔案寫自身 DB received 表（identity、size、digest、published_at）；Target 真相 = 正式檔 + received row，無 `.evidence` 檔。consumer 查詢走 DB：Policy 說不該來 → NOT_EXPECTED，該來且 received 無 → DATA_NOT_READY；不反問 Source | SR-06, T28, RR-03 |
| D16 | Deep check 由 Target 自己滾動讀本地 NAS 重算 digest，`POST /report {kind: VERIFIED}` 回報 Source；Source 比對不符 → 重開該義務（保留原完成紀錄 + 新發現），下輪 pending 重新給 Target 拉 | RC-02, IR-03, T30 |
| D17 | 沒有 CP process。Config（Policy + operational policy + version）為 git repo 中不可變的 `configs/v<N>.json`；發布 = merge 改 `latest` 的 PR（review = 授權，commit = 發布者/時間稽核）；下發走既有 CD pipeline，寫到各 sync 主機本機磁碟 `candidate.json.tmp` → rename。Node 端：驗證（schema、版本遞增、**Policy 段須與 active 完全相同**，否則拒絕並上報）→ rename active→lkg、candidate→active → 熱載入 operational policy。啟動只讀本機 active.json，缺則 lkg，皆缺拒絕啟動。各 Node 曝 `active_config_version` metric 供全域彙整。CD / git 不可用 = 不能發新版，資料流不受影響 | §11, §12, §13, AC-CP-01~03, AC-CFG-01~05, T15, T22, T23, T26 |
| D17 事實 | CI 與 CD 分開；CD 已能部署到 sync 主機。git server 種類與 metrics 收集工具未定；metrics 先以 Spring Boot Actuator 曝 Prometheus 格式 | §16 |
| D18 | Application library 的 Policy 來源 = 本 Node sync service `GET /policy`（sync service 記憶體中 active config 的 Policy 段）；library 記憶體快取 + App 主機本機 fallback 檔；sync service 不可達用快取，首次啟動且無快取 → 拒絕寫入並明確回報。CD 不送 config 到 App 主機。Config 四層：git（真相）→ sync 主機本機檔 → sync service 記憶體 → library 快取 | SR-01, DG-02, §11 |
| D19 | Shallow check 三步：① NFS manifest 集合 vs DB identity 集合，差集 ingest；② 對每個 Target `GET /received?since=<cursor>` 增量比對義務表——Source COMPLETED 但 Target 無 → 重開、Target 有但 Source 未完成 → 補 COMPLETED、digest 紀錄不符 → QUARANTINED；③ 寫 inspection 紀錄（範圍、截止點、比對筆數、unknown 筆數）。Target 不可達的部分標 unknown，保留上次結果與時間 | RC-01, RC-02, RC-04, T11, T19, T27, T30 |
| D20 | Ops 介面：每 Node sync service 提供本地 ops HTTP API（`GET /status` 回 §15 十題的本地答案、retry / pause / trigger-reconciliation / config 檢視），一支 CLI 包它；全域視圖 = CLI 依 Policy 的 Node 清單扇出 `GET /status` 印表，不可達者標 unknown + 上次成功時間；無 Web UI；metrics 以 Actuator 曝出為附加，不是全域視圖的前提。操作授權 = ops API token，操作者 / 時間 / 範圍 / 理由 / 結果寫 DB | §11, §15, §17, AC-CP-03 |
| D21 | 容量：library 自己對 NAS mount statfs（快取 10 s），write 前低於 reject 門檻即明確拒絕不寫；門檻自快取的 Policy 取得。sync service 亦 statfs 供 usable_free_bytes / capacity_alert_status metric 與告警。Target 端拉取前同一段檢查，低於門檻停止拉取並回報 CAPACITY → Source 標 BLOCKED。不透過 `/policy` 傳遞容量狀態 | RT-02, T21 |
| D22 | Pause toward a Target 只在 Source 端：ops 對 Source 下 pause(B) → 義務標 BLOCKED（reason: paused by ops）並自 `/pending` 排除；義務照常計入 backlog 與 age；resume 解除。CLI 扇出可對所有 Source 一次下達。Target 端不做 pause——B 整體維護直接停 B 的 sync service 即可 | §14, §17, T31 |
| 簡化審查 | 已否決的複雜度：`.evidence` 檔（每 Target 最多 9×10⁵ 次/日小檔寫入，重建改用重算 digest）、Abandoned 搬目錄、`/pending` cursor + Target 端退避、三個回報端點（合併為 `/report`）。保留：`/HH/` 小時目錄（否則單日目錄 10⁵ 項）、App 主機 Policy fallback 檔（保護 Local Transaction 不依賴本地 sync service） | — |
| D23 | Application library 介面：`beginWrite(namespace, dataClass, logicalKey)` → WriteHandle（驗 Policy、容量；OutputStream）；`finalize()` → SUCCESS / FAILURE(reason) / PENDING_CONFIRMATION；`discard()` 僅 finalize 前；`exists(identity)` → READY / DATA_NOT_READY / NOT_EXPECTED / UNAVAILABLE（一次 stat `<key>` + Policy 判定，不碰 DB / sync service）；`read(identity)` 僅 READY 時給 InputStream。不提供 list / delete / rename。每個 NFS 操作獨立 thread + timeout。Spring Boot starter 打包；設定僅 mount root、sync service URL、timeout | SR-01, SR-05, SR-06, FR-01 |
| D24 | DB schema（Oracle，sync service 自有 schema）：`file_identity`(source_node, namespace, logical_key, data_class, size, digest, source_ready_at, path)；`obligation`(identity_ref, target_node, state, attempts, next_attempt_at, last_error, completed_at)，索引 (target_node, state, next_attempt_at)；`received`(identity_ref, size, digest, published_at)；`inspection`(scope, cutoff, started_at, finished_at, checked, unknown, diffs, repairs)；`ops_audit`(who, at, action, scope, reason, result)；`target_liveness`(target_node, last_pending_at) | RR-02, RC-04, §14, §16, §17 |
| D25 | 解除 QUARANTINED：release = attempts 清零、next_attempt_at 歸零、狀態回 PENDING，重走完整驗證；Target 正式路徑已有不符檔者，ops 先以 ops API `evict --target <node> <identity>`（寫 audit）刪除再 release。不提供 force-complete | §17, IR-03, T17 |
| D26 | Node 內時鐘：App 主機與 sync 主機 NTP 同步為部署前提；lag 起點 = manifest `source_ready_at`（library 打），終點 = sync service 收到 DONE；增量掃描範圍 = 當前 + 前兩小時，吸收小時邊界偏差 | §16, §18 Measurement, D6, D10 |
